## กราฟที่คัดไว้

1. ความครอบคลุมข้อมูล → 2. ภาพรวมพร้อมความไม่แน่นอน → 3. ความต่างรายสถานที่ → 4. ส่วนประกอบผลต่างของกรณีศึกษา → 5. การเปลี่ยนสัดส่วนรถ → 6. ความไวต่อการจับคู่ → 7. Lockdown ภายใน During

กราฟ 3–5 อาจไม่สร้างหากข้อมูลไม่ผ่านเกณฑ์ โดยบันทึกเหตุผล ไม่เติมผลเก่า รายชื่อกรณีศึกษาคงชื่อสถานที่เดิมแต่ไม่กำหนดล่วงหน้าว่าต้องเพิ่มหรือลด ผลเปลี่ยนตามข้อมูล

ตัดแผนที่ที่ครอบคลุมบางส่วน กราฟปีล่าสุดกลุ่มเล็ก Bubble ซ้ำ รูปแบบวันที่มีวันเดียว และส่วนแบ่งถนนที่ยังไม่ยืนยันครบแขนแยก ออกจากชุดนำเสนอ V4; งานเก่ายังอยู่ครบ

## เปลี่ยน Raw Data

บน Colab เปิด Notebook แล้ว Run all อัปโหลด Excel ใหม่หนึ่งไฟล์ ไม่ต้องแก้โค้ดวิเคราะห์

บนเครื่อง local ติดตั้ง requirements แล้วรันจากโฟลเดอร์นี้:

```sh
python src/pipeline.py --input "C:/path/to/new_workbook.xlsx"
```

ทุกครั้งสร้าง runs/<เวลา UTC>_<hash>/ ใหม่ ไม่ทับครั้งก่อน ภายในมี AUDIT.md, README.md, Presentation.html, Speaker_Notes.md, figures/, tables/ และสำเนาข้อมูลต้นทาง รหัส hash เชื่อมผลกับไฟล์จริง

## Schema ที่รองรับ

ชีต `traffic_data` ต้องมี: survey_date, Date, month, year, covid_period, intersection, road, time_period, passenger_car, pickup_van, large_bus, small_bus, truck, tuk_tuk; id เป็น optional

- Date/month/year เป็นวันเดือนปีรายงาน โดย year ใช้ ค.ศ.
- survey_date รองรับวันที่ Excel, วัน/เดือน/ปี ค.ศ., ISO และชื่อเดือนย่อไทยตามแบบเดิม
- time_period ระบุเวลาเริ่ม–สิ้นสุด เช่น 07:00-09:00
- covid_period ต้องเป็น ก่อนโควิด / โควิด / หลังโควิด โดยตรง ถ้าค่าอื่นจะ audit-only ไม่จัดกลุ่มใหม่เงียบ ๆ
- ช่องว่าง/ขีดของจำนวนรถ=0 ตามข้อตกลง; ค่าติดลบ แปลงไม่ได้ เศษส่วน หรือ survey key ซ้ำถูกบันทึกและกันออก
- ปีรายงานและปีสำรวจต้อง >=2017; ไม่ล็อกสิ้นสุด 2026 ขอบเขตผลอัปเดตตามไฟล์ ไม่อนุมานว่าปีล่าสุดครบปี

ถ้า cleansing เปลี่ยนชื่อคอลัมน์/นิยาม ต้องปรับ mapping อย่างชัดเจนก่อนรัน ระบบไม่ได้เดาว่าคอลัมน์ใหม่หมายถึงอะไร

## ความต่างด้านวิธีจากรุ่นก่อน

V4 กำหนดวันที่สำรวจต้องแปลได้และปี>=2017 เพื่อให้หลักฐานวันครบ จึงอาจได้จำนวนหน่วยต่างจากเดิม; bootstrap 1,000 รอบ seed5001 (เดิม3,000) ไม่อ้างว่า CI ต้องเหมือนเดิม รายงานปีที่ขาดใช้ช่วงปี/เดือนที่พบในไฟล์ ไม่รับรองความครบถ้วนของคลังหน่วยงาน

สำเนา audit_core.py พัฒนาจาก audit เดิม ส่วน pipeline.py ใหม่คำนวณทุกผลจากไฟล์ที่เลือก ไม่มีการอ่าน outputs เดิม

## ส่ง GitHub

แตก ZIP แล้วอัปโหลดโครงสร้างทั้งชุด; ไม่ต้องอัปโหลด Raw Data หรือ runs ส่วนตัวเพื่ออ่านตัวอย่าง มีโค้ดและ Notebook พร้อมตัวอย่างผลแล้ว ยังต้องเติมสมาชิก การแบ่งงาน และบทบาท AI ที่มนุษย์ตรวจจริงตามข้อกำหนดวิชา ไม่ได้เผยแพร่ GitHub อัตโนมัติ


## สิ่งที่เพิ่มใน V4

- แสดง Before/During/After ครบในกราฟภาพรวม กรณีศึกษาประเภทรถ และสัดส่วนรถ
- เพิ่มคอลัมน์ Lockdown และ Not Lockdown (0/1 ตรงข้ามกัน) เพื่อวิเคราะห์เฉพาะ During; หากไม่มีคอลัมน์หรือค่าไม่ถูกต้อง จะข้ามส่วนนี้พร้อมแจ้งเหตุผล
- คง flag ผู้ใช้ ตรวจรายการต่างจากกรอบวันที่ และแสดง sensitivity นิยามอ้างอิงแยก ไม่อ้างเหตุและผล
- ตัวอย่างใช้ไฟล์ (5).xlsx: มี 168 แถวนอกกรอบวันที่อ้างอิงที่ยังให้ Lockdown=1 ผู้ใช้อนุญาตให้ทำต่อพร้อมเปิดเผยข้อจำกัด
- ช่วงอ้างอิงปี 2021 สิ้นสุด 30 ก.ย. เป็นนิยามผู้ใช้ที่ยังต้องยืนยันเอกสารปลายช่วง


ตรวจผลหลังรันด้วย `python verify_v4.py` ต้องมี runs ของไฟล์ตัวอย่างและ fingerprint รุ่นก่อนใน workspace เดิม; validation.json คือผลตรวจที่ส่งมอบ ไม่จำเป็นต้องรัน verifier เพื่อใช้งาน Notebook
