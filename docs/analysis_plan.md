# ขั้นวิเคราะห์หลังตรวจ Feasibility และ Matching Audit

สถานะล่าสุด: ผู้ใช้อนุญาตให้ทำ EDA แล้ว มี Notebook 02 และกราฟ 10 รูปจากไฟล์ใหม่ใน Downloads ข้อความรายการด้านล่างเป็นวิธีดำเนินงาน ไม่ใช่คำขอให้หยุดรออนุมัติใหม่

1. ตรวจรายการ numeric_review.csv, duplicate_review.csv และ report_date_review.csv วันที่รายงานต่างจากวันสำรวจไม่ใช่ข้อผิดพลาด แต่วันที่ปฏิทินที่เป็นไปไม่ได้ยังต้องทวน
2. ตรวจ location_normalization.csv และแหล่งต้นทางของคู่ที่เลือก ไม่รวมชื่อที่คล้ายกันโดยอัตโนมัติ
3. เลือกชุดเปรียบเทียบจาก matching_summary.csv: คู่สถานที่+ช่วงเวลาเป็นชุดกว้าง และคู่สถานที่+ช่วงเวลา+ไตรมาสรายงานเป็นชุดเปรียบเทียบทางเลือก จำนวนแถวไม่เท่ากับจำนวนตัวอย่างอิสระ
4. หลังผู้ใช้ตรวจ audit แล้ว จึงรวมจำนวนรถ 6 ประเภทและหารด้วย period_hours พร้อมติดหมายเหตุสมมติฐาน 0 กลุ่มยังใช้ covid_period เดิม
5. ออกแบบ baseline ภายในชุด location/time/comparable temporal group ที่ตรงกัน และรายงานจำนวนแถว/สถานที่จริงของแต่ละกลุ่ม ไม่ใช้ค่าเฉลี่ยคนละ sample ราวกับเป็น panel เดียวกัน
6. พิจารณากราฟปริมาณรถต่อชั่วโมงตาม covid_period และสถานที่ที่มีข้อมูลเทียบได้ แยกปีในกลุ่ม After เท่าที่ coverage รองรับ ห้ามสรุปการฟื้นตัวปี 2026 ทั้งเมืองจากตัวอย่างน้อย
7. sensitivity checks: ชุดกว้างกับชุดเวลาใกล้กัน, วันที่รายงานกับเดือนสำรวจ, ผลรวมกับสัดส่วนค่าศูนย์ที่สมมติ โดยไม่เปลี่ยนกติกาหลักของผู้ใช้
8. ทุกข้อสรุปมี Evidence, Interpretation, Limitation, Implication และไม่ตีความ vehicle count เป็นความเร็ว/รถติดหรือสาเหตุจาก COVID

งานส่งภายหลัง: Notebook EDA, README ผลที่ตรวจแล้ว, สื่อ Pitching และ Summary PDF พร้อมบทบาทสมาชิกและ AI ตามกติกาวิชา การสร้าง Sites/dashboard/ภาพ AI หรือเผยแพร่ไม่จำเป็นสำหรับ audit ระยะนี้
